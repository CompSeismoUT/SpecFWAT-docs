# Waveform Data

## File structure

Observed waveforms are stored in `fwat_data/${event_name}/` as SAC files. Event names must match the selected source list in `src_rec/`.

| Data type | File name |
| --- | --- |
| Ambient noise, local earthquakes, teleseismic waveforms, teleseismic cross-convolution | `${net}.${sta}.${CH_CODE}${component}.sac` |
| Receiver functions | `${net}.${sta}.${CH_CODE}R.F${gaus}.rf.sac` |

For example, `CH_CODE: BX` and receiver component `Z` select `MX.ST001.BXZ.sac`. The active `NOISE`, `TELE`, or `LEQ` section supplies `CH_CODE` and `RCOMPS`. Receiver functions use the radial component and one file per `TELE.RF.F0` value, formatted with one decimal place, such as `MX.ST001.BXR.F1.0.rf.sac`.

## SAC headers and sampling

The observation reader obtains `npts` and `delta` from the first trace for each event, then checks that every trace has the same number of samples. Prepare consistent sampling across all receivers and components of an event.

- `b`: Beginning time of the waveform in seconds.
- `baz`: Back-azimuth in degrees. The reader requires this header for all data types.
- `dist`: Epicentral distance in kilometers. Supply it for noise group-velocity windows and local-earthquake processing. LEQ explicitly rejects a missing value; noise window selection also uses this distance.
- `t0`: Direct P-wave arrival time in seconds, on the same time reference as `b`. Required for teleseismic waveform and cross-convolution data.

<Callout type="info">
Receiver-function processing sets the reference arrival to zero internally and does not require `dist` or `t0`. Teleseismic waveform processing aligns the observed `t0` with the predicted synthetic P arrival.
</Callout>

The [`ObsData` reader](https://github.com/CompSeismoUT/SpecFWAT/blob/39a9a9b5b7b4cf55b6b327bc90b7ef4f1b6607c5/src/preproc/obs_data.f90) defines file naming and header checks. The examples' forward-only mode (`-r 1`) writes synthetic observations into this same `fwat_data/` structure.
