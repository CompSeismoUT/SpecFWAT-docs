# Model Parameters

## Regular-grid model

SpecFWAT reads regular-grid models in HDF5 format. The root datasets `x`, `y`, and `z` are one-dimensional coordinate arrays in meters. Use increasing, regularly spaced axes and store every model field with Python/HDF5 shape `(len(x), len(y), len(z))`. Coordinates are in the same Cartesian system as the mesh; depth below the reference surface is represented by negative `z` in the supplied examples.

### Isotropic model (`MODEL_TYPE: 1`)

The model file contains:

- `vp`: P-wave velocity in m/s.
- `vs`: S-wave velocity in m/s.
- `rho`: Density in kg/m³.

### Azimuthal anisotropic model (`MODEL_TYPE: 2`)

Use the same `vp`, `vs`, and `rho` fields and add:

- `gcp`: Dimensionless normalized cosine coefficient, $G_c/L$.
- `gsp`: Dimensionless normalized sine coefficient, $G_s/L$.

Here $L = \rho V_s^2$. The solver forms $G_c = \texttt{gcp}\,L$ and $G_s = \texttt{gsp}\,L$ before constructing the elastic tensor. These datasets contain normalized coefficients, not elastic moduli. If the solver model file does not contain both `gcp` and `gsp`, it initializes both coefficients to zero. For the optimization input named by `INIT_MODEL_PATH`, explicitly provide both datasets as zero arrays with the same shape as `vp` when starting from an isotropic model. The optimizer's missing-field fallback allocates zeros using `MODEL_GRID` dimensions before interpolating against the input axes; differing input and inversion-grid dimensions can therefore cause invalid indexing.

The current regular-grid update workflow implements model types `1` and `2`. See the [parameter reference](/docs/preparation/parameter) for simultaneous and alternating parameter updates.

## Solver model and initial inversion model

The solver reads `${TOMOGRAPHY_PATH}/tomography_model.h5`, with `TOMOGRAPHY_PATH` taken directly from `DATA/Par_file`. For example:

```plaintext copy
MODEL           = external
TOMOGRAPHY_PATH = DATA/tomo_files/
```

This selects `DATA/tomo_files/tomography_model.h5`. Set `MODEL_UPDATE.MODEL_TYPE` in `DATA/fwat_params.yml` to the intended parameterization.

`MODEL_UPDATE.INIT_MODEL_PATH` names the starting model used by the optimizer at `M00`. The optimizer interpolates it onto `MODEL_GRID` and saves `optimize/model_M00.h5`. The solver model used to compute the first gradient must represent this same starting model. After updating `M00`, the optimizer writes `optimize/model_M01.h5` and writes the updated model to the solver model path for the next iteration.

The input model grid and `MODEL_GRID` may have different spacing. Ensure both cover the mesh region and use the same coordinate system. See [`read_external_model` and `model_external_values_aniso`](https://github.com/CompSeismoUT/SpecFWAT/blob/39a9a9b5b7b4cf55b6b327bc90b7ef4f1b6607c5/src/patch/model_external_values.f90), [`hti2aniso`](https://github.com/CompSeismoUT/SpecFWAT/blob/39a9a9b5b7b4cf55b6b327bc90b7ef4f1b6607c5/src/patch/aniso.f90), and the [regular-grid optimizer](https://github.com/CompSeismoUT/SpecFWAT/blob/39a9a9b5b7b4cf55b6b327bc90b7ef4f1b6607c5/src/optimization/optimize_grid.f90) for the implementation.
